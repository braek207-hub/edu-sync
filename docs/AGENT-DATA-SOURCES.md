### Что из этого следует для кода

1. **Недобор меряем объёмом трафика** (`AvgTrafficVolume`), не долей выкупа.
2. **Проверка покрытия ничего не отсекает** — пустых значений в витрине нет.
   `MIN_VOLUME_COVERAGE` в `sync/agent/headroom.py` остаётся страховкой на случай,
   если поле перестанет приходить, но защитой от сетей не является.
3. **Сетевые кампании из расчёта недобора исключаются по каналу показа.** Объём у них
   вырожден в константу 100.0: это не «весь трафик выкуплен», а «величина не
   измеряется». Оставленные в расчёте, они получили бы вердикт «выкуплен» и были бы
   вычеркнуты из кандидатов на рост. Канал читается из
   `edu_campaign_settings.settings #>> '{strategy,search|network,biddingStrategyType}'`,
   значение `SERVING_OFF` = канал выключен.
4. **15 кампаний (22 % показов) отсутствуют в витрине настроек** — канал показа
   неизвестен, вердикта они не получают. Это та же слепая зона, которую считает
   `sync/agent/coverage.py::blind_spend`.

### Опровергнутая гипотеза

До замера предполагалось: в сетях API отдаёт «--», `sync/direct.py:117` (`to_num_gas`)
превращает прочерк в ноль, и такой ноль прочитается как «недобор 100 %» — значит
сети зальёт карман разведки. **Неверно.** В сетях приходит 100.0 при полной
заполненности. Ошибка была бы зеркальной: не ложный недобор, а ложное «выкуплен».

## Полнота знаменателя расхода

**Статус: не сверено.** `blind_spend` (`sync/agent/coverage.py`) считает долю расхода,
у которого агент не видел настроек, но знаменатель берёт из `edu_agent_facts` — то есть
из того же Reports API, что и вся витрина. Расход, не попавший в витрину, невидим и для
этого счётчика, поэтому доля выходит оптимистичной.

Чтобы закрыть: один раз сверить сумму расхода витрины за календарный месяц с суммой
в интерфейсе Директа («Общая статистика» по всем кампаниям, привести к одной базе НДС)
и записать расхождение сюда. Совпало — знаменатель полон. Не совпало — в отчёте Э0
нужна вторая строка «расход вне витрины».

## Спрос Wordstat: чего ряд не покрывает

**Замер:** `edu_wordstat_demand`, 5338 строк, 2026-08-25. Наполняется
`sync/edu_demand.py::sync_edu_wordstat_demand` — 19 фраз × 2 региона × недели.
Читается агентом в `sync/agent/demand.py` (режим спроса по направлениям).

### Направления без ряда спроса

`EDU_DEMAND_PHRASES` покрывает четыре уровня образования; направления кампаний
задаёт `sync/classify.py::detect_direction`. Совпадают они не полностью.

| Направление | Фразы спроса | Чем лечится |
|---|---|---|
| `spo` | колледж, техникум, училище, ссуз, среднее профессиональное | — |
| `vpo` | вуз, университет, институт, высшее образование, бакалавриат, специалитет, магистратура, аспирантура | — |
| `dist` | дистанционное обучение, дистанционное образование, заочное обучение | — |
| `dpo` | переподготовка, повышение квалификации, профпереподготовка | спрос есть, **кампаний под него нет** |
| `school` | **нет ни одной** | добавить фразы в `sync/edu_demand.py` |
| `it` | **нет ни одной** | то же |
| `med` | **нет ни одной** | то же |
| `mti` | **нет ни одной** | то же |
| `ntb` | **нет ни одной** | то же |
| `transfer` | **нет ни одной** | то же |

Такие направления получают вердикт `нет ряда`, а **не** `мало данных`: первое
чинится семантикой, второе — временем, и слить их в один вердикт значит спрятать
дыру навсегда. Список печатается в отчёте Э0 отдельной строкой
(`demand_regime.no_series`). Самое дорогое имя в этом списке — `school`: запуск
направления 14.08.2026, то есть там, где ожидания от кампаний нужнее всего,
агент идёт вслепую относительно рынка.

### Регион берётся один — `ru`

В витрине есть оба региона (`ru` = 225, `msk` = 1), но агент читает только `ru`.
Причина не в данных, а в их отсутствии на другой стороне: **гео кампании нигде не
вычисляется.** `sync/classify.py::normalize_city_ip_segment` работает по городу
ЛИДА, а не по настройкам кампании, и сопоставить московский срез спроса с
московскими кампаниями сейчас нечем.

Всероссийский ряд включает Москву, поэтому режим по нему — консервативное
приближение, а не ошибка: у московских кампаний сезон может отличаться, и такого
расхождения агент не увидит. Складывать `ru` и `msk` нельзя — москвичи
посчитались бы дважды.

Закрыть: снимать гео из настроек кампании в `edu_agent_objects` и вести режим
отдельно по каждому срезу. Работа для Ф8.
