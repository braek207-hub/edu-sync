## Ф5. Замкнуть контур «оптимизация → запуск» (агент ↔ билдер)

Сейчас агент крутит ручки существующих кампаний, а билдер собирает новые — и
они не знают друг о друге. Это главный разрыв: 42 % расхода в неокупающихся
кампаниях агент может только придушить, а пересобрать — нет.

1. **Задание билдеру из данных агента.** Агент формирует наряд: какие объекты
   недопокрыты (конверсионные запросы без своей группы), какие кампании
   пересобрать (ROMI < 1 при живом спросе), какие направления расширить.
   Формат — файл-наряд, который принимает `builder.intake`.
2. **Паспорт продукта в агента.** `builder/passport.py` уже строит паспорт из
   лендинга с цитатами. Передать его в смысловой слой (`SEMANTIC_CONTEXT` сейчас
   одна строка) и в генератор гипотез: модель должна судить фразы по продукту,
   а не по общему описанию.
3. **Обратная связь билдеру.** `builder/feedback.py` существует — замкнуть:
   как отработали запущенные кампании (ROMI, качество лидов), чтобы вердикты
   квалификатора и тексты объявлений учились на факте.

Критерий готовности: наряд из агента доходит до `builder.run` без ручной
пересборки, а результат запуска виден в журнале экспериментов агента.

## Ф6. Учиться на деньгах и уважать обучение стратегий

4. **Денежный чекпоинт.** Сейчас вердикт закрывается по эффективным лидам.
   Добавить второй чекпоинт по выручке с поправкой по кривой дозревания
   (49 % за 7 дней, 79 % за 30). Действие получает два исхода: ранний по
   заявкам, поздний по деньгам; расхождение между ними — сигнал «покупаем
   дешёвые, но плохие заявки».
5. **Карта перезапуска обучения.** Свериться со справкой Директа: какие
   изменения сбрасывают обучение стратегии (смена стратегии, смена цели,
   резкое изменение недельного бюджета), какие — нет. Развести действия на
   «безопасные» и «сбрасывающие»; вторые применять, только когда ожидаемый
   выигрыш перекрывает стоимость переобучения, и не чаще кулдауна обучения.
   Сейчас агент двигает целевой CPA, не зная этой разницы.

Критерий: в журнале у каждого действия проставлен флаг «сбрасывает обучение»,
а отчёт показывает, сколько таких за такт.

## Ф7. Полнота картины

6. **Доля выкупа в кривые насыщения.** Колонка `auction_win_share` есть, но
   пустая — заполнить из отчётов Директа и ввести в оценку насыщения: кампания
   с выкупом 30 % не насыщена, ей есть куда расти, даже если DiD этого не видит.
   Сейчас «насыщение» меряется только деньгами.
7. **Слепая зона 15 % (3,0 млн ₽/мес).** Мастер кампаний и прочее вне API —
   закрыть тем же способом, что аудит и геомедийка LIME (сессия + внутренние
   отчёты). Минимум — счётчик слепой доли в каждом отчёте, чтобы решения
   принимались с поправкой на то, чего агент не видит.
8. **Спрос как календарь.** `edu_wordstat_demand` (5338 строк) сейчас не
   привязан к направлениям — смапить фразы на направления и использовать как
   детектор режима: сезонный подъём/спад спроса меняет ожидания, а не
   объявляется провалом кампании.

## Ф8. Генератор идей — полный контур

Сделана только одна ветка: `expansion_candidates` — конверсионные запросы без
своей ключевой фразы (39 кандидатов → 6 после смыслового фильтра, headroom
20 тыс ₽). Нужен весь контур, и он делится на ДВА разных механизма.

**А. Масштабирование проверенного (низкий риск).** Источник — собственный
журнал: связки «объект × сегмент × посадочная», которые уже окупаются с запасом.
Действие — дать им больше объёма: своя группа, отдельная кампания, расширение
гео, снятие ограничений. Гипотеза здесь не нужна — есть доказательство.

**Б. Тесты гипотез (высокий риск, ограниченный бюджет).** Источники:
- растущий спрос Wordstat, который мы не покрываем;
- сегменты и срезы, где конверсия выше базы, но объём мал;
- смысловые гипотезы модели (новая аудитория, новый оффер, новый формат) —
  ТОЛЬКО как предложение человеку, не как автодействие;
- «соседи» окупающихся связок: то же направление, другой город/уровень.

Каждая гипотеза оформляется как эксперимент: ожидаемый эффект, цена теста,
срок, критерий успеха — и живёт в кармане разведки (7 % бюджета, уже есть).
Журнал экспериментов и заповедник тоже готовы — не хватает очереди гипотез и
правила приоритизации (ожидаемая ценность ÷ цена теста).

Критерий готовности: каждую неделю агент выдаёт список «масштабировать N
проверенных связок» + «проверить M гипотез», обе части с числами.

## Ф9. Боевая работа

9. **Первое применение узким скоупом**: `--prod --apply --max-campaigns=3`,
   `target_romi` 1.0 или 2.0 (решение Павла). Сторож в 10:30 следит и
   откатывает, репетиция в 11:00 показывает следующий такт.
10. **Track record по классам действий.** Новый класс проходит shadow:
    пишет «сделал бы, жду N к дате D», не делая; ≥60 % попаданий за 4–6 недель
    → автономия. Инфраструктура ожиданий есть, лестницы автономии нет.
11. **Пейсинг месяца.** План освоения B в систему не заведён: Σ целевых
    прибита к трейлинг-28д. Для сезонного бизнеса это неверно.
