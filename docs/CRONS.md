# Расписание кронов (edu-sync)

Единая карта расписания GitHub Actions синков. Раньше расписание было размазано
по 20 файлам workflow — эта таблица собирает его в одном месте.

## Правило: всё завершается до 09:00 МСК

Павел смотрит дашборды утром. Требование: **все синки отрабатывают не позже 09:00 МСК**.

Старты вынесены на ночь / раннее утро (03:10–05:40 МСК), хотя по сумме длительностей
можно было бы стартовать позже. Причина — **планировщик GitHub Actions опаздывает
на 1–3 часа** относительно заявленного cron-времени (документированное поведение,
не баг проекта). Ранний старт — запас на это опоздание.

Ранний старт безопасен, потому что все синки:
- идут **скользящим окном** (7–30 дней в зависимости от синка);
- **идемпотентны** (delete+insert по дню/окну, либо upsert по ключу).

Если синк стартует до того, как источник (Директ/Метрика/AppMetrica/CRM) закрыл
вчерашний день окончательно — прогон запишет неполные данные за вчера, но
следующий прогон (на следующие сутки) перезапишет их полными. Разовая
неточность на несколько часов не критична — то, что критично, это факт,
что все синки в принципе отрабатывают до того, как Павел откроет дашборд.

## Цепочки зависимостей

- **VK → AppMetrica**: `sync-lime-vk.yml` (03:40) наполняет справочник
  `lime_vk_entities` (кампании VK), по которому `sync-lime-appmetrica.yml` (04:10)
  резолвит установки в кампании. AppMetrica обязана идти строго после VK.
- **Директ + Метрика → sync-lime**: `sync-lime.yml` (04:30, витрина PROCONTEXT)
  собирает данные кабинетов Директа (`sync-lime-direct.yml`, 03:10) и Метрики
  (`sync-lime-ru-metrika.yml`, 03:50) — должна идти после обоих.
- **sync.yml → score-edu-ml**: `score-edu-ml.yml` (05:40) скорит лиды EDU на
  свежих данных из `sync.yml` (04:50, EDU Daily Sync) — должен идти после.
- **build-edu-features → train-edu-ml → score-edu-ml**: недельный цикл ML EDU.
  `build-edu-features.yml` (пн 02:00 UTC) готовит фичи → `train-edu-ml.yml`
  (пн 05:20 МСК) обучает модель → `score-edu-ml.yml` (05:40, ежедневно) скорит,
  используя свежую модель по понедельникам.
- **sync-lime-gcc → лист GCC**: `sync-lime-gcc-sheet.yml` триггерится через
  `workflow_run` сразу после успешного завершения `sync-lime-gcc.yml` (ингест),
  а не по независимому крону — гарантирует, что лист не подтянет неполный ингест.

## Как править расписание дальше

Каждый workflow хранит cron только у себя (`.github/workflows/*.yml`), эта
таблица — производная документация. При изменении времени старта синка:
1. Поменять `cron:` в самом workflow + обновить комментарий рядом с ним (UTC → МСК).
2. Обновить эту таблицу.
3. Проверить цепочки зависимостей выше — не сломался ли порядок.
